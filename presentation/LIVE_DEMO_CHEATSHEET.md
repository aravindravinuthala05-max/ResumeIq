# ResumeIQ Live Demo Cheatsheet

Keep this beside the presentation. Use the existing fictional demo data or the prepared resume and JD from the presentation capture. Do not expose personal information.

## Start

**Application command**

```powershell
python app.py
```

**Browser URL**

`http://127.0.0.1:5000/`

**Useful project paths**

- Resume source: `uploads/` for temporary uploaded files.
- Main dashboard template: `templates/result.html`.
- Frontend behavior: `static/js/result.js`.
- PDF route: `/generate_pdf`.
- Rewriter route: `/rewrite`.

## Demo Setup

Use:

- One PDF or DOCX resume with education, projects, Python/Flask/SQL skills, and at least one measurable result.
- One software-engineering JD with several matching skills and at least one requirement not supported by the resume.
- The fictional capture fixture is generated by `presentation/capture_and_embed.py`; it is not a replacement for the user's own demo file.

## Exact Sequence

1. Open `http://127.0.0.1:5000/`.
2. Show the ResumeIQ landing page and upload area.
3. Select the prepared PDF or DOCX resume.
4. Paste the prepared JD into **Job Description**.
5. Click **Analyze Resume**.
6. Wait for the result dashboard.
7. Show **Overview** and **Resume Health**.
8. Open **ATS / JD Match**.
9. Open **Skills**.
10. Open **Strengths** and **Priority Improvements**.
11. Open **Rewriter** and wait for its cards to load.
12. Compare one **ORIGINAL** and **IMPROVED** card.
13. Open **Interview**.
14. Show a project or technical question and a JD-gap question.
15. Click **Download Report**.
16. Open the generated PDF and show its main headings.

## What to Explain

### Landing page
Say: “The user supplies two inputs: a resume and a target job description.”

### Overview and Resume Health
Say: “This is a quick summary of the current analysis. The health values are existing results, not a new predictive score.”

Expected: ATS score, JD match counts, priority count, interview count, and rewrite status after the rewriter is opened.

### ATS / JD Match
Say: “The weighted ATS result combines resume categories. JD matching separately reports supported and missing skills.”

Expected: circular ATS score, status, and score breakdown.

### Skills
Point to all four groups:

- Resume Skills
- JD-Matched Skills
- Missing JD Skills
- Evidence-Backed Skills

Say: “A JD-only requirement stays missing; it is not converted into candidate evidence.”

### Strengths and Advisor
Say: “The advisor turns evidence and gaps into prioritized recommendations with section and JD context.”

Expected: HIGH, MEDIUM, or LOW recommendation cards, depending on the resume.

### Rewriter
Say: “The original text is preserved. The improved text changes wording only when the rule-based safety checks allow it.”

Show: `ORIGINAL`, `IMPROVED`, source section, evidence, factual-safety label, and copy button.

### Interview
Say: “Questions are generated from resume evidence, supported technologies, projects, experience, and safe JD-gap prompts.”

Expected: project, technical, experience, education, certification, achievement, behavioral, or JD-gap labels.

### PDF/report
Say: “The backend generates a static PDF containing the main analysis headings. The lazily loaded rewriter is outside the existing PDF contract.”

Expected headings: Resume Overview, ATS / JD Match, Strengths, Priority Improvements, Skills, and Interview Preparation.

## Optional Empty-State Demonstration

Only use this if the main demo is stable. Show an analysis where a section is absent and explain that the dashboard displays an intentional empty state instead of inventing content. Do not make the live demo depend on this step.

## Do Not Click

- Do not open raw API payloads or browser developer tools.
- Do not inspect session storage during the presentation.
- Do not use an invalid or oversized file unless specifically demonstrating validation.
- Do not claim that a missing JD skill is a candidate skill.
- Do not describe the current implementation as using an external model or provider.
- Do not navigate through unrelated exploratory pages during the timed demo.

## Quick Recovery

- **Landing page does not open:** confirm the terminal is in the ResumeIQ project folder and run `python app.py` again.
- **Upload error:** confirm the file is PDF or DOCX, readable, and below 16 MB; reselect it.
- **Missing JD error:** paste the JD again and confirm the field is not empty.
- **Dashboard looks incomplete:** wait for analysis to finish, then reload the result page through the normal flow.
- **Rewriter is loading:** wait for the lazy request; if it fails, continue with the already visible ATS, Skills, Advisor, Interview, and PDF sections.
- **PDF does not open:** return to the dashboard and click **Download Report** once more.
